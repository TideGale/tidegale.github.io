RK3568 视频采集与推流终端

2026 秋 · Linux 应用 · 约 2000 行 C

在 RK3568 开发板上打通一条从 USB 摄像头到浏览器的实时链路。采集、解耦、本地预览、HTTP 推流、抓拍、状态查询，全部自己实现，没有用现成的流媒体框架。

  • 采集用 V4L2（Video for Linux 2，Linux 视频框架）的 mmap（memory mapping，内存映射）四缓冲，1280x720 MJPG
  • 中间加环形缓冲，拆两条队列，采集端复制两份，推流和预览各吃各的，谁慢谁丢自己的帧
  • 一帧从队列只取一次，再广播给所有客户端，慢客户端 1 秒发送超时直接踢掉
  • 自写字符设备驱动，把帧率和丢帧数暴露到用户态
15.1 fps摄像头固件上限
0 丢帧推流，32.8 分钟
393采样点
0 增长RSS，28 分钟后

帧率只有 15.1fps，排查了七步才确认不是代码问题：硬件声明支持 30fps、驱动读回也是 1/30、USB 是 480Mbps 高速链路、dmesg 无带宽错误，最后把分辨率降到 640x480，帧率纹丝不动，说明瓶颈在摄像头固件。这个结论写进了 README 的排查表。

智能门锁 · A/B 双分区 OTA

2026 秋 · 裸机 + RTOS · 从零重建

STM32F103RCT6，256KB Flash 切成四块：Bootloader 16KB、两个 96KB 应用槽、4KB 元数据。目标是「能升级」和「升级失败不变砖」这两件事，不是把升级当成附加功能。

  • Bootloader 自己写：读元数据、magic 加 CRC 自校验、选中槽 CRC 校验、校验不过切另一槽、跳转
  • 试启动用 trial 标记加 boot_count 计数，连续三次启动失败自动切回旧槽并清零
  • 新固件先写到另一分区，写完切标记再复位，升级过程断电不会把程序区写坏
  • 外设：AS608 指纹走 UART、4x4 键盘 30ms 消抖只报按下沿、SSD1306 OLED、W25Q128 的 JEDEC ID 读到 0xEF4018
  • 上 FreeRTOS，指纹、键盘、锁体、显示四个任务各自阻塞
0xCBF43926CRC32 标准向量
0 错误擦写 8KB 校验
0xEF4018W25Q128 ID
3 次回滚阈值

每一步都有独立测试分支，切过去能编译运行。CRC32 用标准向量 123456789 对过；把 magic 改成 0x12345678 后上电打印 meta invalid；magic 正确但改 boot_count 不重算 CRC，同样打印 meta invalid，两道检查分别在测。
